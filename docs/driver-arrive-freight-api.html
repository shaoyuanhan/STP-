司机到达与确认运费 · 接口说明

依据：backend/src/routes/external.js（ARRIVE / FINISH）、backend/src/routes/freightBills.js、 docs/api-contract.md 与《TMS-整车发运系统PRD》整理 · 2026-10-20

一、结论先说

  • 司机到达使用独立接口：POST /api/external/shipping-tasks/arrive（状态回传 #12 已按状态拆分为 accept / pickup / arrive / finish 四个接口）。
  • 司机运费回填已补齐：到达时可选传 actualFreight、mileage、arriveTime，并可用 vehicles 逐车回写；不传则沿用计划运费、当前时间。到达即生成待对账运费单。
  • 「确认运费」在管理端由两个接口承担：PUT /api/freight-bills/:id/freight（改运费，留痕）与 POST /api/freight-bills/:id/reconcile（确认对账）。
  • 前端「外部系统模拟」页面已在提交 fdb7c6e 中删除，所以界面上看不到触发到达的入口，只能直接调接口。
  • 与 PRD 的差距已按方案 A 补齐（提交 0b5c2a2 曾移除运费入参），当前实现满足“司机到达后填写运费信息并返回”与“实际运费逐车回写”。

二、司机到达

POST/api/external/shipping-tasks/arrive接口 #12 · 司机到达

请求体

字段类型必填说明
applyNostring二选一发运申请号，优先生效
taskNostring二选一任务单号，兼容定位
carrierNamestring否回传承运商名称，须与任务当前承运商一致；不传按「狮桥物流」留痕
actualFreightnumber否实际运费，≥0；不传按任务计划运费
mileagenumber否里程 km，≥0；写入运费单 mileage
arriveTimestring否到达时间 YYYY-MM-DD HH:mm:ss；不传取当前时间
vehiclesarray否逐车实际运费 [{vin, actualFreight}]；VIN 须属于该任务，合计须与 actualFreight 一致

前置状态与规则

  • 仅 IN_TRANSIT（在途）可到达；PICKED（已提车未出库）、ARRIVED、FINISHED 的处理见下。
  • 状态流转：IN_TRANSIT → ARRIVED，回填 arrive_time（传 arriveTime 用之，否则 NOW()）和 actual_freight（传 actualFreight，否则计划运费）。
  • 多车任务：传 vehicles 按 VIN 逐车回写；未传时把任务实际运费按台数均分。
  • 金额校验：actualFreight/逐车金额须 ≥0；逐车合计与任务实际运费不一致返回 A0002；VIN 不属于该任务返回 A0002。
  • 幂等：已是 ARRIVED/FINISHED 时只补一条状态日志，不覆盖已落库的运费；运费单已存在则直接返回原单号。
  • 到达时自动生成运费单：YF+yyyyMMdd+4位，起始地取任务发运地点、讫地取交付地址（缺省交付地区），mileage 取入参、actual_freight 取实报金额，reconcile_status=0 待对账。
  • 日志来源：传 carrierName 记 CARRIER，不传记 SQ（狮桥）。

附带：司机完结（FINISH）

完结使用独立接口 POST /api/external/shipping-tasks/finish，仅 ARRIVED 可完结：置 FINISHED、回填 finish_time，并同步更新运费单 finish_time。重复回传只记日志。

三、确认运费（管理端）

统一响应信封 { code, message, data }，分页返回 { list, total, page, size }。

GET/api/freight-bills

参数说明
freight_no运费单号，模糊匹配
task_no任务单号，模糊匹配
carrier_id承运商 ID，精确匹配
reconcile_status0 待对账 / 1 已对账
page / size分页，默认 1 / 10

额外返回：amount（当前筛选条件实际运费合计）、plan_amount（计划运费合计）。列表行含 carrier_name、driver_name、customer_name、apply_no、task_status。

GET/api/freight-bills/:id/detail

返回 { bill, adjustLogs }；无修改记录时 adjustLogs 为空数组。调整记录字段：before_freight、after_freight、adjust_reason、operator、create_time。

PUT/api/freight-bills/:id/freight

字段类型必填说明
actual_freightnumber是调整后实际运费，不能与当前值相同
reasonstring是修改原因，≤255 字
  • 仅「待对账」可改；已对账返回 A0002「该运费单已对账，不可修改运费」。
  • 每次修改写一条 freight_adjust_log，操作人固定「系统管理员」。
  • 只改运费单，不会回写任务/车辆明细的实际运费。
{
  "code": "00000",
  "message": "运费修改成功，已记录调整日志",
  "data": {
    "id": 1,
    "freight_no": "YF202610200001",
    "before_freight": 9800,
    "after_freight": 9500,
    "message": "运费修改成功，已记录调整日志"
  }
}

POST/api/freight-bills/:id/reconcile

无请求体。待对账 0→1，回填 reconcile_time = NOW()、reconciler = 系统管理员；重复对账返回 D0001「该运费单已对账，请勿重复操作」。

{
  "code": "00000",
  "message": "确认对账成功",
  "data": { "id": 1, "freight_no": "YF202610200001", "reconcile_status": 1, "reconciler": "系统管理员" }
}

四、与 PRD 的差距

PRD 要求当前实现状态
司机点击到达，体现到达日期 arriveTime 可选回填，不传取 NOW() 已支持
司机到达后填写运费信息并返回；车辆明细实际运费到达后回写 actualFreight/mileage + vehicles 逐车回写，缺省取计划运费并按台数均分 已支持
结算管理展示里程 mileage 写入运费单；未传仍为空，可在管理端查看 已支持（数据来源为司机回传）
修改运费留痕、确认对账 PUT /freight + POST /reconcile 已实现 符合

实现说明

到达接口已独立为 POST /api/external/shipping-tasks/arrive（原 status-sync 已按状态拆分），运费入参不变：不传新字段时按计划运费 + 当前时间 + 空里程 + 按台数均分处理。到达时间须晚于提车/出库时间且不得晚于当前时间。
